When encountering unfamiliar APIs, developers need to know not only which APIs to use but also how to use them. API specifications, API tutorials, and Stack Overflow (SO) provide abundant API knowledge. We regard a tutorial segment or an SO question–answer pair as a knowledge unit (KU), and treat API knowledge retrieval as returning a ranked list of <API, KU> pairs for a natural-language query. However, it is non-trivial to retrieve API knowledge for natural-language queries. Two major problems are the incomplete associations between APIs and knowledge and the static API knowledge retrieval strategies. In this paper, we propose a novel Agentic Knowledge Graph-based approach called RAKG. For the first problem, RAKG designs an API knowledge graph modeling framework based on multi-perspective relevance identification. It first identifies relevant <API, KU> pairs from the lexical, semantic, and structural perspectives, and then builds an API knowledge graph that contains the associations among APIs, among KUs, and between APIs and KUs. For the second problem, RAKG designs a dynamic agentic retrieval strategy, which enables the agent to decide its retrieval steps and stopping point based on the retrieved knowledge, and to verify the retrieved results. We evaluate RAKG with 270 queries on nine Java and Android datasets containing 10,072 <API, KU> pairs. Experimental results show that RAKG outperforms the state-of-the-art approaches, achieving average P@5 and MRR values of 55.85% and 75.05%, respectively. Our user study further confirms that RAKG returns more useful and complementary API knowledge.
